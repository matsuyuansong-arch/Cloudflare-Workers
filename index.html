Start here

先用一句話說明

Cloudflare Workers 是「不用自己養伺服器」的雲端程式執行環境。 使用者送出網頁或 API 請求時，Cloudflare 會在其全球網路上執行你的程式，再把結果回傳。你負責程式與設定，Cloudflare 負責執行環境、擴展與部署。

它特別適合 API、網址轉址、Webhook、存取控制、靜態或全端網站、排程工作，以及需要靠近使用者處理的輕量服務。Workers 採事件驅動模式，不是租一台永遠開著的 Windows 或 Linux 主機。

新手的正確起點 先做一個無資料庫的 HTTP Worker，學會本機預覽、部署與讀取記錄；有真實資料需求時，再加入 D1、KV 或 R2。

01 · Big picture

Cloudflare 不只是一個產品

Cloudflare 是一整套網路、安全、效能與開發者平台。Workers 是其中負責「執行程式」的核心服務之一。

A

網路與效能

DNS、CDN、快取、流量代理與效能最佳化。目標是讓網站更快、更穩。

B

安全

DDoS 防護、WAF、機器人管理、Zero Trust 與存取控制。不同方案的功能與額度不同。

C

開發者平台

Workers 負責運算，搭配 D1、KV、R2、Queues、Workers AI 等服務組成完整應用程式。

工具它做的事什麼時候使用
Workers執行後端、API 或邊緣程式需要依請求執行邏輯
Workers Static Assets提供 HTML、CSS、JavaScript、圖片等檔案靜態網站、SPA 或全端網站前端
Cloudflare Tunnel安全地把既有本機／內網服務接到 Cloudflare程式仍跑在自己的電腦或主機
傳統 VPS提供完整、長時間運作的作業系統需要常駐程序、特殊系統套件或完整主機控制

02 · Use cases

Workers 可以做什麼？

APIWebhook

建立後端 API

接收表單、回傳 JSON、處理第三方 Webhook，或替前端提供資料。

RedirectProxy

轉址與請求改寫

依網址、裝置、語言或登入狀態決定去向，也能調整標頭與回應內容。

StaticFull-stack

發布網站

提供靜態檔案，也能把前端與 Worker API 放在同一個專案。

AuthGateway

認證與 API 閘道

在請求抵達原始系統前驗證權限、限制方法、統一錯誤格式或做速率控制。

CronQueue

排程與非同步工作

定時同步資料、寄送通知，或把耗時工作排入 Queues 後再處理。Cron 以 UTC 設定。

DataAI

資料與 AI 應用

透過 bindings 連接 D1、KV、R2、Durable Objects、Workers AI 等平台資源。

適合與不適合

適合不應直接把 Workers 當成
短時間、事件驅動、可水平擴展的 HTTP 工作永遠開著的傳統伺服器或背景常駐程式
全球 API、轉址、驗證、內容轉換完整 Windows 桌面、Office 或 GUI 執行環境
靜態網站與搭配 bindings 的全端應用未重新設計就直接搬入的重型單機資料庫
輕量排程、佇列、Webhook長時間影片轉檔、巨量 CPU／記憶體運算

03 · Mental model

先建立正確的運作概念

瀏覽器／App送出 HTTP 請求
→
Cloudflare 網路把請求交給 Worker
→
Worker執行程式並回傳 Response

最基本的 Worker 就是一個函式：收到 Request，執行判斷，再產生 Response。需要資料時，不把資料存在程式記憶體，而是透過 binding 存取 D1、KV、R2 或其他服務。

無伺服器（Serverless）

不代表「沒有伺服器」，而是不用自己安裝、修補與擴展伺服器。平台依請求啟動程式並計量。

邊緣運算（Edge）

程式由 Cloudflare 網路處理，通常可在接近使用者的位置回應，減少繞回單一機房的距離。

無狀態（Stateless）

不要假設下一次請求仍會使用同一份記憶體。要保留的資料必須寫入適合的儲存服務。

Binding

Worker 與資料庫、儲存桶、AI 或其他 Worker 的安全連接。程式透過 env 使用它。

05 · Prerequisites

開始前準備

確認 Node.js 與 npm

PowerShell
node --version
npm --version

兩行都應顯示版本號。若出現「無法辨識」或找不到命令，先安裝／更新 Node.js，再重新開啟 PowerShell。

不要全域安裝 Wrangler 當唯一版本 Cloudflare 建議把 Wrangler 裝在每個專案裡，讓團隊與不同電腦使用相同版本。透過 npx wrangler 執行即可。

06 · Hands-on

實作：第一個 Worker API

這個練習會建立三個網址：首頁說明、健康檢查，以及可接收名字的 JSON API。

  1. 建立專案 在你要放專案的上層資料夾開啟 PowerShell，執行：
    PowerShell
    npm create cloudflare@latest -- my-first-worker
  2. 依提示選擇 選擇 Hello World、Worker only、JavaScript、使用 Git，第一次先不要部署。選項文字可能隨工具版本微調，以「純 Worker + JavaScript」為目標即可。
  3. 進入專案並啟動本機預覽
    PowerShell
    Set-Location .\my-first-worker
npx wrangler dev
    預設會提供 http://localhost:8787。這個 PowerShell 視窗要保持開啟。
  4. 修改 src/index.js 用下列內容取代範例程式：
src/index.js
function json(data, status = 200) {
  return new Response(JSON.stringify(data, null, 2), {
    status,
    headers: {
      "content-type": "application/json; charset=utf-8",
      "cache-control": "no-store"
    }
  });
}

export default {
  async fetch(request) {
    const url = new URL(request.url);

    if (request.method !== "GET") {
      return json({ ok: false, error: "只接受 GET 請求" }, 405);
    }

    if (url.pathname === "/health") {
      return json({ ok: true, status: "healthy" });
    }

    if (url.pathname === "/api/hello") {
      const rawName = url.searchParams.get("name")?.trim() || "訪客";
      const name = rawName.slice(0, 50);

      return json({
        ok: true,
        message: "你好，" + name + "！",
        time: new Date().toISOString()
      });
    }

    if (url.pathname === "/") {
      return new Response(
        "Cloudflare Worker 正常運作。\n" +
        "請試試 /health 或 /api/hello?name=Yuansong",
        { headers: { "content-type": "text/plain; charset=utf-8" } }
      );
    }

    return json({ ok: false, error: "Not Found" }, 404);
  }
};

測試三個網址

PowerShell（另開一個視窗）
Invoke-WebRequest -Uri 'http://localhost:8787/'
Invoke-RestMethod -Uri 'http://localhost:8787/health'
Invoke-RestMethod -Uri 'http://localhost:8787/api/hello?name=Yuansong'
成功標準 首頁回傳文字；/health 的 ok 是 true；/api/hello 回傳問候與 UTC 時間。任意其他路徑應回傳 404。

你剛才學到的核心

  • request.method：判斷 HTTP 方法。
  • new URL(request.url)：拆解路徑與查詢參數。
  • Response：設定內容、狀態碼與回應標頭。
  • 輸入要驗證與限制長度；不能直接相信使用者傳入的資料。

07 · Deploy

部署並取得公開網址

部署是對外狀態變更 執行部署後，程式會出現在公開網路。先確認範例中沒有密碼、API key、個資或內部網址。
  1. 登入 Cloudflare
    PowerShell
    npx wrangler login
    Wrangler 會開啟瀏覽器，請在 Cloudflare 頁面確認授權。
  2. 部署
    PowerShell
    npx wrangler deploy
  3. 記下網址並做煙霧測試 Wrangler 會輸出類似 https://my-first-worker.<你的子網域>.workers.dev 的網址。
PowerShell：把網址換成自己的
$workerUrl = 'https://my-first-worker.YOUR-SUBDOMAIN.workers.dev'
Invoke-RestMethod -Uri ($workerUrl + '/health')
Invoke-RestMethod -Uri ($workerUrl + '/api/hello?name=Yuansong')

第一次啟用 workers.dev 後，若短暫看到 523，可稍候片刻再測試。正式、關鍵業務建議使用自己的 Custom Domain 或 Route，而不是只依賴 workers.dev。

建議保留的專案檔

檔案／資料夾用途
src/index.jsWorker 的主要程式
wrangler.jsonc名稱、進入點、相容日期、bindings 與部署設定
package.json依賴與 npm 指令
package-lock.json鎖定實際套件版本，應提交 Git
.gitignore排除 node_modules、機密與本機暫存

08 · Static assets

如何發布單檔 HTML？

Cloudflare 對新專案建議使用 Workers Static Assets 來發布靜態網站、SPA 或全端應用。若只有一個 HTML，也可以把它放在專案的 public 資料夾。

  1. 建立靜態網站專案
    PowerShell
    npm create cloudflare@latest -- my-static-site
    在建立精靈中選擇 Hello World → Static site。
  2. 把網頁放入 public 將你的單檔 HTML 命名為 index.html，放到 public 資料夾。
  3. 本機預覽
    PowerShell
    Set-Location .\my-static-site
npx wrangler dev
  4. 部署
    PowerShell
    npx wrangler deploy
重要：網站上線，不等於資料會同步 如果你的 HTML 把資料存在瀏覽器 localStorage，資料仍只存在該瀏覽器與該裝置。換電腦、清除瀏覽器資料或使用無痕模式都可能看不到。多人共用需另外設計後端，例如 Worker + D1；原有工具仍應提供 JSON 匯出與匯入備份。

09 · Routing

綁定自己的網域

Worker 要接收網路請求，常見有三種入口：

方式用途例子
workers.dev快速開始、個人或測試用途my-api.example.workers.dev
Custom DomainWorker 本身就是此主機名稱的來源api.example.com
RouteWorker 放在既有來源伺服器前方處理指定路徑www.example.com/api/*

控制台設定 Custom Domain

  1. 網域必須已加入 Cloudflare。
  2. 進入 Workers & Pages，選擇你的 Worker。
  3. 開啟 Settings → Domains & Routes。
  4. 選擇 Add → Custom domain，輸入完整主機名稱，例如 api.example.com。
  5. 等待 DNS 與憑證生效後，使用 HTTPS 實測。
Route 最常見的錯誤 Route 需要對應的 Cloudflare 代理 DNS 記錄。少了橘色雲朵代理記錄，請求可能根本不會抵達 Worker。若 Worker 就是來源，優先考慮 Custom Domain。

10 · Data

KV、D1、R2、Durable Objects 怎麼選？

服務適合資料典型用途注意
KVKey → Value設定、快取、偏好、允許／拒絕清單讀多寫少；最終一致，不適合即時庫存扣減
D1關聯式資料會員、表單、訂單、內容管理採 SQLite SQL 語意；先設計 schema 與 migration
R2檔案／物件圖片、影片、附件、匯出檔S3 相容；費用包含儲存與操作
Durable Objects需要協調的狀態聊天室、WebSocket、訂位鎖定、每使用者狀態用於強一致與協調，不是所有 API 的預設資料庫
Queues待處理訊息寄信、縮圖、Webhook 重試、批次處理非同步；設計重試、冪等與失敗處理

一個實務判斷法

要查表、排序、關聯

選 D1。

用一個 key 很快取值

選 KV，但接受最終一致。

要存圖片或大型檔案

選 R2。

不能發生重複訂位

評估 Durable Objects 或具交易保證的資料設計。

常見組合 Worker 處理 API → D1 存結構化資料 → R2 存附件 → Queue 處理非同步工作。bindings 只授權 Worker 存取明確連接的資源。

11 · Configuration

環境變數與機密

一般設定可放環境變數；API key、token、密碼與連線字串必須放 Secret。兩者都會透過 env 交給 Worker，但 Secret 的值不會在控制台或 Wrangler 中再次顯示。

正式環境新增 Secret

PowerShell
npx wrangler secret put WEATHER_API_KEY

依提示貼入值。不要把機密直接寫在 wrangler.jsonc 或程式碼。

程式中讀取

JavaScript
export default {
  async fetch(request, env) {
    const apiKey = env.WEATHER_API_KEY;

    if (!apiKey) {
      return new Response("缺少必要設定", { status: 500 });
    }

    return new Response("Secret 已載入，但不會輸出它的內容。");
  }
};

本機開發

在 Wrangler 設定檔旁建立 .dev.vars 或 .env，二選一，不要同時混用。並把它加入 .gitignore。

.dev.vars
WEATHER_API_KEY="local-development-value"
.gitignore
.dev.vars*
.env*
node_modules/
若曾把機密提交到 Git 刪除檔案不代表歷史中的值消失。立即撤銷／輪替該機密，再處理 Git 歷史；不要只做一次新 commit。

12 · Operations

記錄、除錯與回復舊版本

本機除錯

  • 用 npx wrangler dev 重現問題。
  • 用 console.log() 記錄必要資訊，但不要輸出 token、密碼或完整個資。
  • 測試正常路徑、404、錯誤 HTTP 方法、缺少參數與過長輸入。

查看線上即時記錄

PowerShell
npx wrangler tail

也可以在 Worker 的 Observability／Logs 頁面查詢執行記錄。新建立的 Workers 目前預設啟用 Workers Logs；既有專案仍應檢查設定。

版本與部署

每次程式或設定變更都會建立版本；部署決定哪些版本正在接收流量。若只想先上傳版本供預覽，不立即切換正式流量，可使用：

PowerShell
npx wrangler versions upload

回復舊版本

PowerShell（會立刻改變正式流量）
npx wrangler rollback

也可在控制台 Worker → Deployments，選擇舊版本右側選單後 Rollback。

程式可以回復，資料不一定能回復 Worker 版本不會替 KV、D1、R2 等資料狀態建立相同時間點的回復。若新版已改變資料結構或刪除 binding，直接回復舊程式可能失敗。正式系統要另外規劃 migration 與資料備份。

常見問題快速診斷

症狀先檢查
找不到 npm／nodeNode.js 是否安裝，重開終端機後再執行版本檢查
本機可用，線上 500Secret／binding 是否部署、相容日期、線上 logs
瀏覽器出現 CORS 錯誤預檢 OPTIONS、允許來源／方法／標頭；CORS 不等於認證
Custom Domain 找不到網域是否在 Cloudflare、DNS／路由是否正確、憑證是否完成
Route 完全沒觸發對應 DNS 記錄是否存在並啟用 Cloudflare 代理
資料剛寫入 KV 卻讀到舊值KV 是最終一致；需要強一致時重新選擇資料模型

13 · Cost

免費額度與費用觀念

以下為 2026-08-18 查核的 Workers 核心額度摘要。Cloudflare 會調整方案、限制與計價，正式上線前應重新查看官方 Pricing 與 Limits。

項目Workers FreeWorkers Paid／Standard
請求每日 100,000 次每月含 1,000 萬次，超額依量計費
CPU 時間每次呼叫 10 ms每月含 3,000 萬 CPU ms；單次上限依類型與設定
記憶體128 MB128 MB
基本費用無月費帳戶最低每月 US$5
Workers 資料傳出核心 Workers 計價不另收資料傳輸／頻寬費；相連服務仍有自己的計價
  • D1、KV、R2、Queues、Workers AI 等各有獨立用量與額度，不能只看 Workers 請求數。
  • Free 的 CPU 10 ms 是運算時間，不是整個 HTTP 請求經過的牆鐘時間。
  • 先用 Analytics 觀察請求、錯誤與 CPU；對外開放的 API 要防止濫用。
  • 第三方 API、寄信、簡訊、AI 模型與資料庫也可能產生成本。

14 · Safety

上線前安全檢查

不要把 Worker 當成「隱藏前端 API key」的魔法盒 Secret 能避免 key 出現在瀏覽器，但你的公開 Worker 端點仍可能被任何人呼叫。還要加上認證、驗證、速率限制、用量監控與必要的來源限制。

15 · Next steps

依需求選下一條學習路線

A

公開單檔 HTML

Workers Static Assets

先把 index.html 放進 public，本機預覽、部署，再綁 Custom Domain。

B

多人共用表單

Worker + D1

設計資料表、migration、輸入驗證、登入權限、備份與管理介面。不要再依賴 localStorage 當共享資料庫。

C

上傳圖片或附件

Worker + R2

設計檔案大小與格式限制、物件 key、授權下載、生命週期與清理機制。

D

定時同步外部資料

Cron Trigger + Queue

排程負責觸發，Queue 負責緩衝與重試。Cron 使用 UTC，台灣時間要換算。

建議學習順序

  1. Request、Response、HTTP 方法與狀態碼。
  2. Wrangler：dev、deploy、tail、versions。
  3. Git 與預覽部署。
  4. Secrets、bindings 與資料模型。
  5. 測試、觀測、成本與安全。
  6. 有真實需求後，再選 D1／KV／R2／Durable Objects／Queues。
給 Python 使用者 Workers 目前也提供第一級 Python 支援，可使用 FastAPI、Pydantic 等支援套件並透過 FFI 存取 Runtime APIs。新手仍建議先用本手冊的 JavaScript 範例理解平台模型，再依專案需求切換 Python。

16 · FAQ

常見問題

一定要買網域才能使用嗎？
不用。部署後可先使用 Cloudflare 提供的 workers.dev 子網域。正式業務再綁定自己的 Custom Domain 或 Route。
Workers 和 Cloudflare Pages 有什麼差別？
兩者歷史定位不同，但能力逐漸整合。對新的靜態、SPA 與全端專案，Cloudflare 官方目前建議使用 Workers Static Assets。既有 Pages 專案不需要只因名稱不同就立刻搬遷。
我可以用 npm 套件嗎？
很多套件可以，但 Workers runtime 不是完整傳統 Node.js 主機。平台支援一部分 Node.js APIs，部分套件需要 nodejs_compat，仍應查看相容文件並實測。
Workers 可以連接 Google Sheets 嗎？
可以透過 Google API 或自己的中介服務呼叫，但要妥善處理 OAuth／服務帳戶、權限、配額與機密。不要把憑證放在前端 HTML 或公開 Git。
把 localStorage 網頁部署後，員工就能共用同一份資料嗎？
不會。localStorage 仍是每個瀏覽器各自保存。要共用資料，需要 D1、Google Sheets、外部資料庫或其他後端，並加入登入、授權與操作記錄。
可以把 Worker 當成 24 小時常駐 Bot 嗎？
Worker 主要由 HTTP、排程、Queue 等事件觸發，不是傳統常駐程序。請改成事件驅動設計；需要長流程時再評估 Workflows、Queues 或其他執行環境。
如何避免一次部署就影響全部使用者？
使用 Git、預覽 URL、wrangler versions upload 與部署管理。較成熟的專案可採漸進式部署，把部分流量導向新版本，再逐步擴大。
